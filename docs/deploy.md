# Deploying Lulu CRM (free tier)

| Part | Where | Notes |
| --- | --- | --- |
| Web app (`apps/web`) | Vercel | The link people open |
| API (`apps/api`) | Render, from `render.yaml` | Docker; sleeps after 15 minutes idle on the free plan |
| PostgreSQL | Neon | `DATABASE_URL` |
| Redis (BullMQ) | Upstash | `REDIS_URL`, starts with `rediss://` |

The web app forwards `/api/v1/*` to the API (`API_PROXY_TARGET` in `apps/web/next.config.ts`), so the
browser only talks to the Vercel address.

## API on Render

New → Blueprint, pick the repo. Render reads `render.yaml` and asks for the `sync: false` values:
`DATABASE_URL`, `REDIS_URL`, `CORS_ORIGIN` (the Vercel link), `SEED_OWNER_PASSWORD`, `SEED_MEMBER_PASSWORD`,
`API_PUBLIC_URL` (the Render API link, for the OAuth callback), and, for live Google LSA,
`GOOGLE_ADS_DEVELOPER_TOKEN`, `GOOGLE_ADS_CLIENT_ID`, `GOOGLE_ADS_CLIENT_SECRET` and optionally
`GOOGLE_ADS_LOGIN_CUSTOMER_ID`. `JWT_SECRET` and `ADS_TOKEN_ENCRYPTION_KEY` are generated by Render.
`ADS_PROVIDER_<PLATFORM>` defaults to `simulated`; Google LSA can be set to `live` once its three
Google Ads credentials are set. The other platforms stay on `simulated` until C2-C4, and `live` for
them stops the API at startup.
On every start the container applies migrations; with `SEED_ON_START=true`
it also loads the design's sample data. The live workspace runs with `SEED_ON_START=false` (emptied of sample data
on Oct 23, 2026), so records people create stay as they are.

To empty the business data again (contacts, companies, deals, tasks, notes, activities, segments, imports, AI
results), keeping the workspace, sign-in accounts, pipeline stages and settings, run this in Neon's SQL editor:

```sql
TRUNCATE ai_insights, import_rows, import_jobs, activities, notes, tasks, deals, segments, contacts, companies;
```

## Web app on Vercel

Root directory `apps/web`. Environment variables:

```
NEXT_PUBLIC_USE_MOCK=false
NEXT_PUBLIC_API_URL=/api/v1
API_PROXY_TARGET=https://<the Render link, no trailing slash>
```

Merging to `main` redeploys both.
